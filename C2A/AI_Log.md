## 2. AI 使用的时间轴

### 阶段 1：问题理解（10 min）

**用户输入**：C2A Challenge 任务说明 + 4 项交付物 + 5 项评分标准。

**我的处理**：

1. **拆解评分标准**——把 100 分拆为 5 个维度，识别权重分布。
2. **识别核心张力**：
   - "基准设计"权重最高（25%）→ 工程性最重要。
   - "AI 使用质量"占 20% → 必须可追溯。
   - "复盘质量"占 20% → 必须有真反思，不能套话。

**AI 价值**：帮助我快速拆解评分标准，把模糊任务变成可操作的工程目标。

**人类决策**：保留 4 项交付物结构，不擅自增加。

---

### 阶段 2：文献与设计参考（20 min）

**Prompt 给自己的反思清单**：

```
1. 现有 AGI/LLM 评测的痛点是什么？
2. 哪些维度被严重忽视？
3. 防作弊的关键设计模式？
4. 信度/效度如何工程化？
```

**AI 协助产出**（基于训练知识 + WebSearch）：

- 现有评测痛点清单（MMLU 饱和、HumanEval 模板刷分、ARC 单维度局限等）。
- 8 维度框架的灵感来源（认知心理学中的"流体智力/晶体智力" + BigBench 的多任务思路 + ARC 的程序合成题）。
- 反事实变体设计思路（来自因果推断文献）。

**人类决策**：

- 决定不照搬任何现有基准，而是融合。
- 决定加入"价值边界（VAL）"维度，因为现有基准对 AGI 安全覆盖不足。
- 决定加入"元认知（MET）"维度，因为"知道自己不知道"是 AGI 区别于狭义 AI 的关键。

---

### 阶段 3：撰写 Proposal（30 min）

**写作思路**：

1. 先写 TL;DR（控制 5 句话内）。
2. 再写"为什么需要 C2A"（痛点+判断）。
3. 再写"如何设计"（原则+框架+评分+防作弊）。
4. 最后写"如何落地"（里程碑+风险）。

**AI 协助**：

- 提供结构化模板（TL;DR / 背景 / 设计 / 实施）。
- 检查论证逻辑漏洞（"答对率"和"认知能力"的关系是否充分论证）。
- 校验权重合理性（4 项评分权重之和=1.0）。

**人类决策**：

- 把"价值边界"维度列为正式维度（而非附加）。
- 把"反事实稳健性"从"防作弊手段"升级为"评分组成"（权重 20%）。
- 拒绝给"评分 LLM"赋 0 误差承诺，承认局限。

---

### 阶段 4：设计 Benchmark（45 min）

**核心工程产出**：

1. **8 维度的题目样例**——为每个维度手写 1 个 seed + 1 个变体示例。
2. **变体生成器伪代码**——抽象出 8 种 mutation 类型。
3. **Task Unit YAML Schema**——确保工程可落地。
4. **评分协议**——4 个组件的实现细节 + LLM-judge Prompt 草案。
5. **验证实验**——信度/效度/抗污染/难度梯度。

**AI 协助**：

- 把我的"反事实变体"想法形式化为可执行的 mutation 类型清单。
- 帮我写出 LLM-judge 的 prompt 草案（多维度评分设计）。
- 校验 YAML schema 的完整性。

**人类决策**：

- 题目样例全部由人写出（AI 不能凭空捏造高质量 ARC 题）。
- LHP 维度选择 8-puzzle 而非复杂棋类（算力可控）。
- 评分协议中保留了"双 LLM 投票"而非"单 LLM"，强调对 LLM-judge 偏差的警觉。

---

### 阶段 5：撰写 AAR（计划中）

**AAR 框架（来自 Army 传统）**：

```
1. 初始计划 (Initial Plan)
2. 实际发生 (What Actually Happened)
3. 差异原因 (Why It Differs)
4. 经验教训 (Lessons Learned)
5. 改进行动 (Improvement Actions)
```

**AI 价值**：提供 AAR 框架模板 + 提醒"避免套话、要具体"。

**人类决策**：必须真实记录本任务的"踩坑"与"妥协"，不接受 AI 的"完美总结"。

## 3. 关键提示词记录

### P1：设计原则提取

```
我: "我要做一个 AGI 认知评测基准。请从'科学性'角度列出
    5 条不可妥协的设计原则，每条附上'为什么不可妥协'。"

AI 提议：信度 / 效度 / 客观性 / 可重复 / 抗污染

我: "前 3 条是常识。第 4 条合并到第 1 条。重点改：原则要
    反映'认知能力'的特殊性，要区分'答题'和'认知'。"

最终：5 条铁律（不可记忆 / 过程可解释 / 维度独立 / 难度可控 / 抗污染）
```

**反思**：AI 第一轮回答偏通用化；通过追问逼出了更精准的 5 条原则。

---

### P2：维度选择

```
我: "我要给 AGI 认知能力分维度。请列出 8-12 个候选维度，
    每个用一句话解释'测什么'。"

AI 提议：12 个维度（含"情感理解"、"幽默感"等）。

我: "情感和幽默不在'认知'范畴。砍掉。同时确保每个维度
    都有可工程化的题型。"

最终：8 个核心维度（ABS / CAU / COU / TRA / MET / CRE / LHP / VAL）
```

**反思**：AI 容易把"AI 能力"和"人类能力"混淆；人类监督纠正了边界。

---

### P3：评分权重

```
我: "A=答对率, R=推理, K=反事实稳健, E=解释忠实。请给
    权重。要论证合理性。"

AI 提议：A=0.5, R=0.2, K=0.2, E=0.1

我: "答对率仍是基础，但要降。重'过程'。调整后重新论证。"

最终：A=0.40, R=0.25, K=0.20, E=0.15
```

**反思**：AI 默认"答对率至上"，与本任务"过程优先"原则冲突；通过对话重塑权重。

## 4. AI 输出的关键采纳与拒绝

### ✅ 采纳

| 提议 | 来源 | 采纳理由 |
|---|---|---|
| 8 维度框架 | AI 提议框架 + 人类筛选 | 既有认知科学依据又有可工程化题型 |
| 三件套（Stem+变体+自解释） | AI 协助形式化 | 体现"过程评分"原则 |
| Cronbach α ≥ 0.85 | AI 提议阈值 | 心理测量学标准 |
| 探索性因子分析验证 | AI 提议 | 验证维度独立性 |
| 双 LLM 投票评分 | AI 提议 | 缓解 LLM-judge 偏差 |

### ❌ 拒绝

| 提议 | 拒绝理由 |
|---|---|
| 12 个维度（含情感/幽默） | 不属于"认知"范畴 |
| A=0.5 权重 | 与"过程优先"原则冲突 |
| "完美无偏 LLM-judge"承诺 | 不诚实，承认局限 |
| 一次性发布全部题目 | 增加污染风险，改分阶段 |
| "0 误差"等绝对化表述 | 改用"≥"、"期望"等可验证语言 |

## 5. AI 使用的元反思

### 5.1 AI 在本任务中的优势

- **结构化输出**：把模糊任务拆解为可执行步骤。
- **知识检索**：把分散的认知科学/评测文献串成体系。
- **格式规范**：YAML Schema、文件结构、Prompt 模板。
- **跨域联想**：把 ARC（程序合成）和 TRA（迁移）联系起来。

### 5.2 AI 在本任务中的局限

- **过度通用化**：第一轮原则提议偏通用化。
- **默认权重倾向**：偏向"答对率"传统思路。
- **创造具体题目的能力有限**：ARC/CAU 等题需要人工构造。
- **缺乏领域判断**：无法独立判断哪些维度该合并、哪些该拆分。

### 5.3 协作模式总结

```
人类主导：任务理解、价值判断、关键决策、原创题目
AI 协助：结构化、形式化、查漏补缺、模板生成
互相校验：每一步都有"AI 提议 → 人类决策 → 反思"
```
