# C2A — Measuring the Cognitive Capacity of AGI

> **Challenge**: C2A · 衡量 AGI 的认知能力
> **Submission Type**: Proposal + Benchmark + AI Log + AAR
> **Date**: 2026-10-10
> **Status**: Submitted

---

## 0. TL;DR

我们提出 **C2A Benchmark**（Cognitive Capacity Assessment for AGI），一个面向"通用人工智能认知能力"的**多维、抗污染、可解释**评测基准。它围绕 8 个核心认知维度展开，每个维度包含**合成生成题 + 反事实变体 + 自解释评分**三件套，用以同时衡量"答对"与"懂为什么答对"。我们相信：衡量 AGI 的认知能力，不是测"它能不能答对这道题"，而是测"它能否在未见过的认知结构上稳定地、可解释地、可迁移地工作"。

---

## 1. 背景与动机

### 1.1 现有评测的三大痛点

| 痛点 | 表现 | 后果 |
|---|---|---|
| **数据污染** | 模型在训练阶段见过原始题目或近似题 | 分数虚高，无法反映真实能力 |
| **单一指标** | 几乎所有基准只看"答对率" | 抹平推理深度差异，奖励"押题"模型 |
| **过程不透明** | 只看 final answer，不看 reasoning | 无法区分"真懂"与"猜对" |

参考案例：

- **MMLU** 在 GPT-4 之后基本饱和（>88%）。
- **GSM8K** 的"数学推理"得分很大程度上是模板匹配。
- **HumanEval / MBPP** 的代码题被证实可被记忆式刷分。
- **ARC** 的题目虽然设计精良，但单维度的格点变换难以反映完整认知能力。

### 1.2 我们的核心判断

> **AGI 的认知能力 ≠ 答题准确率。**
>
> 它至少包含三层：**(a) 抽取规则，(b) 跨域迁移，(c) 解释自身认知边界**。

当前基准大多只覆盖 (a)，且连 (a) 也常因污染而失真。因此本提案的**第一原则**是：**评测"理解"而非"记忆"，评测"过程"而非"答案"**。

---

## 2. 设计原则（5 条铁律）

| # | 原则 | 落地方式 |
|---|---|---|
| P1 | **不可记忆 (Non-Memorizable)** | 题目由程序合成生成 + 反事实扰动，绝不引用公开数据集 |
| P2 | **过程可解释 (Process-Explainable)** | 每道题必须提交"推理轨迹"，由独立评分 LLM 评判 |
| P3 | **维度独立 (Dimension-Orthogonal)** | 8 个维度彼此正交，避免单一能力横扫 |
| P4 | **难度可控 (Difficulty-Calibrated)** | 每题带"难度等级 (1-5)"，便于分层评估 |
| P5 | **抗污染 (Contamination-Resistant)** | 题目延迟发布 + 评测时生成新种子 + 答案哈希校验 |

---

## 3. 评测框架：C2A 的 8 个认知维度

我们参考了认知科学、AGI 安全、ARC/ConceptARC、BigBench、MMLU 的设计教训，将"认知能力"拆解为 **8 个维度 + 1 个综合维度**：

```
                        ┌──────────────────────┐
                        │   C2A 综合得分 (C)   │
                        └──────────┬───────────┘
                                   │
        ┌──────────┬──────────┬────┴─────┬──────────┬──────────┐
        ▼          ▼          ▼          ▼          ▼          ▼
   抽象规则    因果推理   反事实    迁移学习   元认知    创造性    长期规划    价值边界
   ABS         CAU        COU       TRA       MET       CRE       LHP       VAL
```

| 维度 | 测什么 | 典型题型 |
|---|---|---|
| **ABS** 抽象规则抽取 | 从样例中归纳变换规则 | ARC 格点变换、程序合成 |
| **CAU** 因果推理 | 在混淆中识别真实因果 | 干预/观察区分、反向因果 |
| **COU** 反事实推理 | "如果……会怎样" | 假设世界扰动下的推演 |
| **TRA** 迁移学习 | 跨域应用已学规则 | 把 ARC 规则迁移到自然语言/数学 |
| **MET** 元认知 | 模型能否评估"自己不知道什么" | 置信度校准、错误自检 |
| **CRE** 创造性 | 在约束下生成新颖解 | 受限生成、多解评估 |
| **LHP** 长期规划 | 多步、稀疏奖励下的策略 | 棋类残局、规划谜题 |
| **VAL** 价值边界 | 对指令的伦理边界识别 | 模糊指令下的安全行为 |

每个维度包含 **15 道种子题 + 100 道生成变体**，总数约 920 题。

## 4. 题目结构：每题 = 三件套

```
┌────────────────────────────────────────────┐
│  Task Unit (TU)                            │
│                                            │
│  1) Stem (题干)         ← 唯一种子部分    │
│  2) Counterfactual Variant (反事实变体)   │
│  3) Self-Explanation Slot (自解释槽)       │
│                                            │
│  Submit: {answer, reasoning_trace, conf}   │
└────────────────────────────────────────────┘
```

**为什么这样设计？**

- **Stem**：唯一固定部分，确保题目锚点稳定。
- **Counterfactual Variant**：在不改变认知结构的前提下扰动表面变量。如果模型只"记忆 stem"，变异后分数会大幅下降；如果它真"理解结构"，分数保持。
- **Self-Explanation Slot**：强制模型提交推理过程。评分时不仅看 answer，还看 reasoning 是否被 LLM-judge 判定为"自洽且忠实"。

## 5. 评分机制

我们设计 **C2A Score** 为一个加权综合得分：

$$
C = w_a \cdot A + w_r \cdot R + w_c \cdot K + w_e \cdot E
$$

| 符号 | 含义 | 权重 | 取值范围 |
|---|---|---|---|
| A | 答对率（stem + 变体均对） | 0.40 | [0, 1] |
| R | 推理轨迹质量（LLM-judge） | 0.25 | [0, 1] |
| K | 反事实稳健性（变体得分 / 原题得分） | 0.20 | [0, 1] |
| E | 解释忠实度（解释 ↔ 答案一致性） | 0.15 | [0, 1] |

权重设计依据：
- 答对率仍是基础（40%），但不再是唯一信号。
- 推理过程与解释忠实度合计 40%，体现"过程评分"。
- 反事实稳健性 20% 是"抗污染保险"，防止模型靠记忆刷分。

## 6. 防作弊设计

| 攻击 | 防御 |
|---|---|
| 模型刷原题 | 题目延迟发布 + 评测时程序生成新变体 |
| 训练时见过 | 仅种子题公开；正式评测题由加密种子生成 |
| 抄推理模板 | LLM-judge 推理轨迹的**特异性**与**结构对应** |
| 多账号猜测 | 每个 stem 配 5-10 个变体；猜测得分上限低 |
| 评分 LLM 被攻陷 | 双盲评分 + 答案哈希 + 时间窗口采样 |
| Prompt 注入 | 题目输入与系统提示严格隔离（结构化输入） |

## 7. 基线方案（Baseline）

我们建立 4 类基线：

1. **Human Ceiling**（人类专家天花板）：由 50 名研究生做完整测试，得分作为"上限"。
2. **Human Floor**（普通人基线）：100 名 MTurk 工人，提供"下限"与"难度梯度"。
3. **Current SOTA LLMs**：GPT-4o、Claude-3.5、Gemini-1.5、Llama-3.1-405B、Qwen2.5-Max。
4. **Random / Heuristic Baseline**：随机答 + 简单启发式（验证难度梯度合理性）。

---

## 8. 验证指标（科学性论证）

| 指标 | 期望值 | 检测方法 |
|---|---|---|
| **信度 (Reliability)** | Cronbach α ≥ 0.85 | 内部一致性分析 |
| **效度 (Validity)** | 维度间相关 r < 0.6 | 探索性因子分析 |
| **天花板/地板** | 人类天花板 < 95%, 地板 > 5% | 基线对照 |
| **抗污染** | 见过原题的模型得分高于未见过模型 ≥ 15% | A/B 实验 |
| **难度梯度** | 难度等级与得分单调相关 | Spearman 等级相关 |
| **稳定性** | 同一模型不同种子下得分波动 < 5% | 多次评测 |

## 9. 里程碑（90 天）

```
Week 1-2  │ 设计 8 个维度的种子题 (8 × 15 = 120)
Week 3-4  │ 实现变体生成器 + 自解释评分协议
Week 5-6  │ 内部预评测 (GPT-4o / Claude-3.5 / 人类)
Week 7-8  │ 信度/效度分析 + 难度梯度校准
Week 9-10 │ 大规模评测 + 排行榜建立
Week 11-12│ 公开文档 + 论文撰写 + 开源题目集
```

## 10. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 评分 LLM 偏差 | 高 | 多 LLM 一致性投票 + 人工 spot-check |
| 题目泄漏 | 中 | 种子题与变体分离发布 + 加密生成 |
| 维度难以独立 | 中 | 因子分析验证，必要时合并 |
| 算力瓶颈 | 中 | 难度分级采样，小模型先筛 |
| 定义争议 | 低 | 公开征求社区反馈 |

- **核心团队**：3 人（认知科学 / 评测工程 / AGI 安全）

---

## 12. 为什么 C2A 与众不同

1. **过程优先**：A 是答案，但 R/K/E 加起来比 A 还重。
2. **反事实稳健性**：拒绝"记忆型高分"。
3. **元认知维度**：测"知道自己不知道"。
4. **价值边界维度**：测"知道什么不该做"。
5. **持续演化**：题目可通过合成器持续生成，**基准不会过时**。

---

## 13. 总结

> **衡量 AGI 的认知能力，不是给模型做试卷，而是建一面能够照出"它真正懂什么"的镜子。**

C2A 提出了一种**多维、过程、抗污染、可持续**的评测框架，并在评分机制、信效度验证、防作弊设计上均给出了可执行的工程方案。我们相信这套方案不仅是一份"竞赛提案"，更是一份**可持续迭代的认知评测基础设施蓝图**。
