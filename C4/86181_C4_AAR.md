## 3. 为什么会有差异？

**主观：**
- 第 4 轮首测即崩（datetime 序列化）：写 payload 时只清洗了顶层列表、漏了嵌套结构——对"深拷贝式清洗"缺乏条件反射，属于编码习惯问题。
- 第 6 轮打包浪费一次往返：把含反斜杠转义的复杂 Python 代码直接塞进 bash 命令行，转义被吃掉。

**客观：**
- CHALLENGE.md 声称 .skill 是 tar.gz，但官方实物是 ZIP——文档与实物不一致，靠"先验实物"补救（这也是本次最有价值的经验）。
- Windows 下 Git Bash 的 tar 对 `D:` 路径有历史遗留问题，验证环节被迫改道。

**根因归纳：** 两个 bug 和一次返工都指向同一件事——**首版只验证了"主路径"，没有第一时间跑边界用例**。凡涉及序列化/编码/路径的任务，边界测试必须前置。

## 4. 下次怎么做？

- **P0**：写完任何脚本，立即执行固定边界测试清单（空输入/未知 ID/深层嵌套/自检/中文路径），把它做成 prompt 模板片段，不靠临场想起。
- **P1**：涉及"按规范生成文件"的任务，第一步先找一个真实样本做格式基准（本次 ZIP vs tar.gz 的教训），再动手。
- **P2**：复杂打包/转义命令一律落成脚本文件执行，不在命令行内联多行 Python。
