## 第 1 轮 · 选题决策（人主导，AI 提供分析）

- **我的指令：** "这是 C4 挑战任务（CHALLENGE.md 全文）。帮我分析评判标准，并从我过往挑战成果里找一个'人人用得上'的技能方向。"
- **AI 产出：** 分析出最高权重是"被使用次数"而非"技术深度"；扫描了 D:/挑战任务成果/ 下 C1、C2、C2A、C2G 四个文件夹，发现共同点：每个挑战都强制交 AI 日志 + AAR，且现有 AAR 全靠手写、无数据支撑。
- **我的判断：** **采纳**。方向定为"数据驱动的 AAR 生成器"——用户痛点真实（本人每个挑战都在重复做）、受众最大化（全体成员每挑战必用）、演示数据现成（四个历史挑战文件夹可做真实测试）。
- **关键取舍：** 否决了"法学出题器"方向——虽然也是我的高频能力，但群内受众太小，违背 C4"被最多人使用"的取胜逻辑。

## 第 2 轮 · 规格研究（先看清标准再动手）

- **我的指令：** "查看官方示例 skill-explainer.skill 和 wechat-doc-mapper.skill 的实际打包格式。"
- **AI 产出：** 用 file + unzip 检验，发现**实际是 ZIP 包**（尽管 CHALLENGE.md 写的是 tar.gz），根目录为技能名，含 SKILL.md（YAML frontmatter + 触发短语）+ scripts/ + references/。
- **我的判断：** **采纳并推翻了文档字面描述**——按实物格式（ZIP）打包。期间踩坑：Git Bash 的 tar 读 `D:` 路径报 `Cannot connect to D: resolve failed`，改用"先复制再解包"验证。此坑后来写进了教学说明的常见坑 ②。

## 第 3 轮 · 架构设计（三层结构 + 双引擎）

- **我的指令：** "按官方三层加载机制设计技能：确定性计算交给脚本，判断性写作交给 AI 指令，挑战注册表用数据文件驱动。要求脚本零第三方依赖。"
- **AI 产出：** 定稿架构——SKILL.md（五步工作流+9 种边界情况）、scripts/aar_extractor.py（扫描/时间线/轮次统计/缺口检查四引擎）、references/aar-template.md（四问模板+写作红线）、references/deliverables.json（C1–C10H 注册表）。
- **我的判断：** **部分采纳并修改**：注册表从常规的 YAML 改为 JSON——YAML 需要第三方库，JSON 标准库直读，"陌生人复制即跑"优先级更高。

## 第 4 轮 · 编码与首测（暴露 bug #1）

- **我的指令：** "写完脚本后，在 D:/挑战任务成果/C2G 真实数据上运行测试。"
- **AI 产出：** 脚本首版 350 行；首测即崩——`TypeError: Object of type datetime is not JSON serializable`。根因：AI 日志条目里的 mtime 字段没进 JSON 序列化清洗。
- **我的判断：** **打回重做**。要求"用递归清洗函数一次性解决，不要逐处打补丁"。修复后 C2G 测试通过：4 文件 / 10,466 字 / 轮次信号 27 处 / 缺口 0。

## 第 5 轮 · 边界测试（暴露 bug #2 + 注册表误报）

- **我的指令：** "补边界测试：空文件夹、未知挑战 ID、深层子目录、对 C4 自身做缺口自检。"
- **AI 产出：** 四组测试三个新发现——
  1. **bug #2**：空文件夹直接 KeyError 崩溃（时间线 dict 缺 active_days 键）→ 修复为优雅告警 + 空骨架；
  2. **注册表误报**：C1 的术语表实际叫 `glossary.json`，模式 `*术语表*` 匹配不上 → 校准模式后 C1 缺口从 2 → 0；
  3. **自举验证**：对开发中的 C4 文件夹跑缺口检查，正确报出 4 项缺失（skill说明/教学说明/demo/AI日志）——技能用自己的缺口检查规划了自己的交付。
- **我的判断：** **采纳**。空文件夹从"崩溃"改为"优雅降级"是正确决策：报错退出还是给出空骨架？选择后者，因为空骨架本身就是"这个挑战还没产出"的复盘证据。

## 第 6 轮 · 打包与文档（含 1 次返工）

- **我的指令：** "打包为 .skill 并验证完整性，然后写五件交付文档。"
- **AI 产出：** 首次打包命令因 bash 转义把 `\\` 吃掉导致 Python 语法错误 → 返工为脚本文件方式打包（此经验：复杂打包命令落成 .py 文件执行，不写在命令行里）。最终包：4 文件 / ZIP_DEFLATED / testzip 完整性 OK。
- **我的判断：** **采纳**。文档按"skill说明 / 教学说明 / demo / AI日志 / AAR + README"六件套产出，命名全部符合 `*C4*` 规范。

## 经验沉淀（下个挑战的 prompt 模板怎么改）

1. "先检验实物格式再照做"（第 2 轮的 ZIP 发现）值得固化进指令：**任何"按规范生成文件"的任务，第一步先找一个真实样本做格式基准**。
2. "边界测试清单"（空/未知/深层/自检）应作为固定 prompt 片段，在写完任何脚本后立即执行，不依赖临场想起。
